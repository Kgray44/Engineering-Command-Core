## Owner walkthrough

1. **Projects.** Open either Project Library and inspect the appearance editor and saved views. In an authorized test namespace, move a card by pointer or keyboard and reload. Open a Project with recorded work to inspect Overview, Tasks, Milestones, Dependencies, GitHub and verification, Telemetry, Acceptance, History, and Artifacts. Follow a linked PR or CI run and return to its Project. In Telemetry, expand Recent recorded attempts and follow a receipt to its Task card.
2. **Merge.** Find either walkthrough PR with its linked Project or Task name. Compare the observed source context, prerequisite summary, and integration history. After configuring the scoped GitHub credentials, preview required checks for the displayed head. Use Voyagewright #901 for the failing case and verify the exact job against the linked GitHub result. Keep the acceptance pass read-only.
3. **Voyagewright.** Compare the Projects, Tasks, Merge, Activity, and Settings links with the canonical Voyagewright palette on desktop and mobile. At phone width, open **Menu** to reach any engineering workspace. Tab to a destination or dismiss the menu with Escape. Review the same workspaces on desktop and repeat the navigation with reduced motion enabled.
4. **Settings and diagnostics.** In an authorized test namespace, save and reload a preference, then use the category reset. Open Activity, Connections, and Data & Backup to review their actual observations and verification timestamps.

## Owner decision and external inputs

- Both read bindings were absent from canonical staging environment revision 2 at the November 22 readiness check. Install `AETHERWAKE_GITHUB_READ_TOKEN` and `VOYAGEWRIGHT_GITHUB_READ_TOKEN` as independent repository-scoped secrets on the canonical [Aetherwake staging Site](https://ecc-aetherwake-stage.kgamazing44.chatgpt.site). Then verify PR detail and exact-head checks from both signed-in origins. Keep credential values in Sites. [Credential setup and troubleshooting](docs/deployment.md#staging-github-read-credentials)
- Obtain an authorized consistent hosted database export and any applicable file inventory, then restore into a separate target. Compare source and restored schema, identities, relationships, and file digests where applicable. The available Sites connector provides bounded inspection, and Sites version rollback restores code. [Recovery guide](docs/operations.md#troubleshooting-and-recovery)
- Record the owner decision on [draft PR #2](https://github.com/Kgray44/Engineering-Command-Core/pull/2) after reviewing the staged workflows and remaining evidence. Keep the production cutover decision in [Phase 1B](PHASE1B-SITES.md).
